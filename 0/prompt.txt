## 3. Architecture changes

### Merge navigation and extraction

Replace the separate navigation → extraction → progress interpretation cycle with one structured decision per observed state.

That decision may:

- Emit sparse facts from the current page.
- Select relevant document links, table regions, or list pagination.
- Define a table/form mapping.
- Choose up to eight actions whose targets are already observable.
- Identify unresolved evidence gaps.

Use separate extraction calls only for selected documents or content too large for the current decision. Capture the source snapshot before background work proceeds.

The model continues choosing where to navigate, what to search, and which sources matter. After navigation, obtain a new observation and decision. Code executes model-selected pagination and field operations; it does not invent routes or crawl all sources.

### Introduce explicit internal interfaces

Keep the public answer schema and Decimal resolver. Add lightweight internal records:

| Record | Purpose |
|---|---|
| `Observation` | Snapshot ID, URL, frame, controls, content regions, table structure, and change summary. |
| `Decision` | Snapshot-bound facts, selected sources/regions, bindings, actions, and missing evidence. |
| `ActionResult` | Applied operations, field readbacks, errors, and resulting snapshot. |
| `Coverage` | Which selected records/pages were read, ordering, exclusions, and completeness evidence. |

Adapt extracted records into existing `KINDS`. Preserve raw values, locale, source IDs, and evidence excerpts.

### Replace repeated rows and copied values with bindings

For regular tables, the model chooses the relevant table and maps headers to fact fields once. Python then parses the selected rows exactly, including raw number strings and row provenance.

For forms, the model maps visible fields to computed answer data paths. Python supplies values and verifies readbacks. The model no longer needs to reproduce the full bid repeatedly.

Reuse mappings only within the same run and matching structure. Invalidate on changed headers, field meaning, frame, or control identity. Irregular prose and ambiguous tables return to Qwen.

Stop action batches on unexpected navigation, changed target identity, rerender, ambiguity, or errors. Keep TAN requests and final signing outside speculative batches.

### Shrink repeated context without discarding evidence

Each decision receives:

- Current mission and unresolved gaps.
- Current relevant region and control map.
- The last two action outcomes.
- Only needed facts and applicable extraction fields.

Remove repeated full histories, large null-filled schemas, the complete tool catalogue, and repeated full answers. Keep exact source evidence available through handles rather than reinserting it.

Replace silent document truncation with complete, tracked chunks. Unread chunks remain explicit gaps.

Unify extraction caching and concurrent duplicate suppression. Keys include run/session, source identity, content hash, schema version, and relevant reference/date context. Replace substring URL matching with exact source IDs.

### Schedule work from facts, not mission barriers

Overlap brief extraction with browser attachment. Start each site worker when its own browser is ready.

Start ERP work for a requirement group as soon as that group’s specification is usable. Do not wait for the entire specification mission. Let the model route unresolved facts when private sites distribute information differently.

Use one UI owner per tab and structured cancellation. Await cancelled work before freezing final evidence.

Default to eight concurrent Qwen calls per run, with four slots available for interactive decisions and four for background work. Reserve a separate limit of four Clef decisions.

### Make completion prove correctness

Replace “a fact exists” early exits with coverage sufficient for the resolver:

- Exact reference and authorized sender.
- Latest applicable dated record before the cutoff.
- Required revision and withdrawal handling.
- Relevant price tiers, stock, conditions, and candidate coverage.
- Evidence supporting a no-bid decision.

Share eligibility checks with the resolver to prevent contradictory rules. Recheck specific contradictions or missing evidence instead of rereading whole collections.

Preserve deterministic financial validation and exact-reference TAN correlation. Final submission requires verified field readbacks, summary consistency, and a signed acceptance receipt.

Qwen remains the default, with thinking disabled. Test Clef only for choosing among at most eight observed controls, with an abstain option. Qwen handles interpretation, commercial facts, revisions, ambiguity, and signing.

Accept Clef routing only if the paired development comparison preserves full quality and reduces both total tokens and runtime. Invalid choices or abstention return to Qwen. Do not add a Qwen validation call after every Clef choice. [Hosted-model interfaces](https://ehl-challenge.atira.ai/start.md)

For navigation, replace stacked 20-second waits with a whole-attempt fast-path budget: four seconds to commit plus two seconds for functional readiness, with one read-only recovery attempt and a maximum of twelve seconds across both attempts. Apply this consistently to guards, helpers, back navigation, and popups.

Use readable current-document state and actionability, not network-idle or character count alone. Never blindly replay an ambiguous write, TAN request, or final submission. [Playwright navigation semantics](https://playwright.dev/python/docs/api/class-page#page-goto), [actionability](https://playwright.dev/python/docs/actionability)
